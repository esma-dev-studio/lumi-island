# ユーザビリティテスト報告(v3)

判定の区分: `Automated test` / `Visual review` / `Human usability test` を分け、
自動テストの成功だけで子ども向けUXをPASSにしない。

## 1. 人間によるブラインドプレイテスト — **NOT TESTED(未実施)**

指示された体制(最低3名: 小学生相当1名・ゲームに慣れていない成人1名・開発を知らない成人1名)は
本作業環境では実施できないため、**未実施**と記録する。PASSとはしない。

実施時の手順書(準備済み):
1. README・口頭説明なしで新規ゲームから開始してもらう
2. 計測: 最初のNPCへ話しかけるまで / 最初の依頼受注まで / 最初の採取まで / 最初のクラフトまで /
   NPC不在時に取った行動 / 睡眠方法を理解できたか(**観察項目**・合否判定には使わない) /
   釣り依頼を完了できたか / 迷った回数 / 操作説明を求めた回数 / ルミの木開花まで到達できたか /
   楽しかった場面 / 分かりにくかった場面
3. 受入基準: 3名中3名が最初の依頼を2分以内に受注 /
   3名中3名が進行不能にならない / 3名中2名以上が開花まで到達 /
   同じ場所で2名以上が迷ったらUIまたはレベルデザインを修正

   注: v3までの受入基準にあった「3名中3名が追加説明なしで睡眠」は**外した**(補助機能のため
   観察項目に格下げ)。睡眠は自由探索・時間調整の補助であり、メイン依頼の進行には不要
   (依頼中のNPCは questCritical で常に対応可能。v3最終回帰の11分34秒走行も睡眠0回で完走)。
   睡眠が理解できたかは引き続き観察・記録するが、公開判定の必須条件とはしない。

## 2. ブラックボックスUXボット(`npm run test:ux`)— 部分達成

画面に表示された情報だけで遊ぶ自動試験(内部状態・座標・目標ID・inventory・デバッグAPIを
一切読まない。読み取りは「いまやること」の文・進捗/距離表示・画面端矢印・NPCマーカー・
ホットヒント・「とじる(Esc)」表示のみ。操作は通常のキーとクリックのみ)。

| 計測項目 | 結果(3走行) |
|---|---|
| タイトル→ゲーム開始 | 6〜22秒(安定) |
| 最初の会話が開くまで | 10〜28秒(3走とも成功) |
| **最初の依頼の受注まで** | **12〜29秒(3走とも成功・受入の2分以内)** |
| 木材採取 | 最良走行で4/5(0〜4/5と不安定) |
| 報告→次の依頼 | 未到達 |

所見:
- 「話を聞く→受注」までは、画面の誘導(目標文+マーカー+ヒント)だけで毎回迷わず到達できる。
- 採取フェーズは「木がどこにあるか」を視覚で見つける場面で、DOM情報しか持たないボットは
  探索が不安定になる(人間は木が見えるため本質的に易しい)。ここから先の子ども向け判定は
  人間テストの領分であり、自動化で代替しない。
- 走行中に「工房カウンターでEを押すと店が開いて閉じ方に迷う」ケースをボットが再現した。
  画面には「とじる(Esc)」が明示されており人間は脱出可能だが、人間テスト時の観察ポイントとして記録する。
- コンソールエラー: 全走行で0件。生ログ: `.logs/ux_result.json`(保存されている最新走行は
  `"result": "timeout"` / `gathered: false` — 受注は15秒で成功、木材採取に到達できず721秒で打ち切り)。
- **現状の実績を一文で言うと**: 「最初の依頼の受注まで(12〜29秒)は安定して達成できるが、
  木材採取は最良4/5で完走していない」。UXは**改善中**であり、達成済みとは書かない。
  v4で採取Objectiveの誘導先を最寄りの未採取ノードへ動的化する導線改善に着手している
  (`.logs/ore_path_analysis.md` の修正3)。**効果は未計測**のため、再走行するまで判定は変えない。
