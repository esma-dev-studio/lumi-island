# ルミ島のくらし — iPad タッチ操作 UX検証 (touch_audit_v17)

`debug=1` は状態の読み取り(座標・目標・もちもの)にだけ使い、テレポート・アイテム付与は1回も使っていない。

## 0. 結論

**タッチだけで序盤を完走できた。** タイトル →「はじめから」→ ツムギの会話 → 木をきる →
カマ・ツリザオのクラフト → 桟橋で釣り(サカナ1匹)→ ランタンのクラフトと 島への家具配置 →
第1章の依頼5本目まで、指だけで進んだ。**console エラーは 0件**、
**44x44 未満のタップ対象は 0**、**タップが別の要素に吸われる箇所も 0**。
ダブルタップ拡大・ピンチ拡大・長押しの選択メニューも、どれも起きなかった(実測)。

いちばん大きい問題は3つ。

1. **クラフト・ずかんのパネルは 中身の 9〜23% しか画面に出ていないのに、
   「下にまだある」ことを示すものが ほとんど無い。** とくに、目標カードが名指しした
   「いしのランプ」は、クラフトを開いても 画面に出ていない(自動で見せに行かない)。
2. **右下の丸ボタンが「押すもの」ではなく「できない理由」になる場面がある。**
   配置中の「しぜんの めぐみの ばしょだよ」など。押しても何も起きず、しかも 13.3px の3行。
3. **いちばん使う指のボタンの文字だけ 14px 未満**(てをふる 10.8px / 右上メニュー 12.2px)。
   パネルの中は 15〜18px で読みやすいので、そこだけ ちぐはぐ。

## 4. 発見(重要度で絞らず 全件)

### F-01 【確信度: 高】目標が名指ししたレシピが、クラフトを開いても画面に出ていない

- 目標カード: 「ざいりょうが そろったよ! 右上の『クラフト』ボタンで いしのランプを作ろう」。
- ところが `.panel.craft-panel` は `scrollHeight 2730〜2973 / clientHeight 621`(**見えているのは 21〜23%**)。
  「つくる」ボタンは 25個あり、パネルの見える範囲(y 98〜719)に 完全に入っているのは **5個だけ**
  (y=272,384,450,516,582)。6個目(y=694)は 下が切れ、のこり **19個は y=760 以降**で 画面に出ていない。
- 一覧の並びは「あたらしい!」→「どうぐ」→「かぐ」…の順で(`src/ui/CraftUI.ts:298-313`)、
  目標のレシピが上に来る仕組みは無い。`src/ui/CraftUI.ts` に `scrollIntoView` は 1か所も無い。
- iOS はスクロールバーを ふだん隠すので、「下にまだ ある」手がかりは **行が半端に切れていること だけ**。
- 証拠: スクショ 37(カマ・ツリザオは見えるが はなだんの行が半分切れている)、スクショ 108
  (「いしのランプを作ろう」と言われているのに、画面には はっぱの木・かべどけい・ベリージャム・
  ほんのやま・ウッドベンチ・カマ しか無い)。
- 影響: 子どもが「言われたものが 無い」と感じて 詰まる、いちばん可能性の高い場所。

### F-02 【確信度: 高】ずかんは 中身の 9% しか画面に出ない

- `.panel.codex-panel` 590x623 @(295,98)、`scrollHeight 6670 / clientHeight 621` = **9%**。
  バッジタブでも 3560/621 = 17%(スクショ 203 / 205)。
- スクロール自体は 指でできる(`src/ui/style.css:352-355` の
  `overflow-y:auto; touch-action: pan-y; -webkit-overflow-scrolling: touch; overscroll-behavior: contain;`)。
  問題は **量と手がかりの無さ**。
- タブ(「ずかん」85.5x45 /「バッジ 0/114」127.3x45 /「アルバム 0/24」137.3x45)は 44px以上で合格。

### F-03 【確信度: 高】右下の丸ボタンが「できない理由」になり、押しても何も起きない

- 配置モード: ラベルが **「しぜんの めぐみの ばしょだよ」**(116x116 の丸の中に font 13.3px で3行)。
  同じ文が 画面中央下の帯にも出ているので二重(スクショ 69 / 83)。
- 屋外でも **「つかまえるには 虫あみが ひつよう」**(スクショ 70)。
- しくみ: `src/ui/TouchControls.ts:347` が HUDのヒントを そのままボタンのラベルにしている
  (`label = hintToLabel(f.hint)`)。ヒントは「できない理由」も流してくるので、
  ボタンが 説明板になってしまう。`dim` も付かないので 押せそうに見える。
- 影響: 「押すところ」が「読むところ」に変わる。子どもは押して、何も起きず、もう一度押す。

### F-04 【確信度: 高】いちばん使う指のボタンの文字が 14px 未満

| 要素 | ラベル | 大きさ | font-size | 出どころ |
|---|---|---|---|---|
| `.touch-emote` | てをふる | 76x76 | **10.8px** | `src/ui/touch.css:144` `font-size: 0.6rem` |
| `.touch-btn` | もちもの / クラフト / おねがい / ずかん / しゃしん / メニュー | 63x58(ずかんのみ 58x58) | **12.2px** | `src/ui/touch.css:194` `font-size: 0.68rem` |
| `.touch-action.long` | 長いラベルのとき | 116x116 | **13.3px** | `src/ui/touch.css:104` `font-size: 0.74rem` |

- `html.touch-ui { font-size: 18px }`(`src/ui/style.css:921`)が rem の基準なので、
  0.6rem = 10.8px、0.68rem = 12.24px、0.74rem = 13.32px。
- パネルの中は 15.1〜18px(`.panel-close` 15.1px /`.craft-btn` 15.8px /`.title-btn` 18px)で
  読みやすいので、**指で いちばん触るボタンだけ 小さい** のがちぐはぐ。
- ついでに 14px未満の表示文字(押すものではない): `.obj-head`「いまやること」12.96px
  (`style.css:926` 0.72rem)、`.help-sec` の節見出し 13.3px(`style.css:650` 0.74rem)、
  `.title-credit` 12.6px(`style.css:658` 0.7rem)。

### F-05 【確信度: 中】丸ボタンをもう一度押すと 店に入り、その間 スティックが消えて動けない

- ツムギに報告した直後、同じ場所で もう一度 丸ボタンを押すと **ツムギ工房の店** が開いた(スクショ 20)。
- 店が開いているあいだ `TouchControls.sync` は `panelOpen` で スティックと丸ボタンを消す
  (`src/ui/TouchControls.ts:362-366`)。つまり **指では1歩も動けない**。
- 抜け道は 右上の「とじる」(81.7x44)だけ。詰みではないが、
  「歩けなくなった」と感じる時間ができる。実際に検証ボットは ここで 8分ぶん 足ぶみした。

### F-06 【確信度: 中】左上の目標カードが 開いたパネルに重なる

- `.obj-hud` は `left: sa-l+14 / top: sa-t+14`、`max-width: 40vw`(= 1180px 幅で 472px。`style.css:925`)。
  パネルは中央寄せで 左端が x=310(実測、`.panel.craft-panel` 560x623@(310,98))。
- ラベルが2行になると カードの右端(最大 486px)が パネルの左上に かぶる。実際に かぶっている(スクショ 37)。
- どちらも `#ui-root` の直の子で z-index を持たないため、DOM順で カードが上に描かれる。

### F-07 【確信度: 中】トーストが 開いているパネルの上に出る

- スクショ 37: 「クラフトの『くみあわせ』タブで いろいろ ためしてみよう…」のトーストが
  クラフトパネルの右端(「つくる」の列)に かぶっている。
- `.toast-box` は `right: sa-r+14px`(`style.css:874`)・`bottom: sa-b+268px`(`style.css:931`)で、
  中央のパネル(幅 560〜680)と 横に重なる余地がある。
- `.toast-box` は `pointer-events: none`(`style.css:62`)なので **タップは吸わない**。見た目だけの問題。

### F-08 【確信度: 中】たてむきの案内バーが 仮想スティックの帯に重なる

- 実測(たてむき 820x1180): `.rotate-hint`「よこむきに すると あそびやすいよ」 **323.7x47 @(248,957)**。
- `.touch-stick-zone` は `width: min(46%,460px) = 377px` / `height: min(56%,430px) = 430px` で
  左下 = x 0..377 / y 750..1180(`src/ui/touch.css:25-32`)。
- 重なる帯は **x 248..377 / y 957..1004**。`.rotate-hint` は `z-index: 40`(`style.css:1009`)で
  タッチUI(z-index 6)より上、しかも クリックで消えるハンドラ付き(`src/main.ts:143`)。
- つまり、たてむきで遊びはじめた最初の5秒、左下の右上あたりに指を置くと
  **案内が消えるだけで スティックが出ない**。スクショ 214。

### F-09 【確信度: 中】そうさほうほうが 半分も読めない(よこむき)

- タイトル画面(よこ): `.title-extra` `scrollHeight 826 / clientHeight 348` = **42%**(スクショ 02)。
- ポーズメニュー(よこ): `548x298`、`scrollHeight 757 / clientHeight 296` = **39%**(スクショ 211)。
- 17行の一覧のうち出ているのは「うごく」「さわって つかう」の2節まで。
  「しらべると できること」「がめんを ひらく」は スクロールしないと読めない。
- たてむきでは 826/708 = **86%** まで良くなる(スクショ 218)。
- 中身は タッチ版で正しい(「W A S D」は出ない=実測 false)。

### F-10 【確信度: 低】ポーズメニューだけ タイトル行に「とじる」が無い

- ほかのパネルは `.panel-close`「とじる」81.7x44。ポーズは「つづける」280x50 で閉じる
  (`src/ui/PauseMenu.ts:68-76`)。機能は足りているが 閉じかたが画面ごとに違う。

### F-11 【確信度: 低】右上のボタンだけ幅がそろわない

- 「ずかん」だけ 58x58、ほかは 63x58(文字数の差。`min-width: 58px` + 文字幅)。
  押しやすさには影響しないが、並びが不ぞろいに見える。

### F-12 【確信度: 低】丸ボタンと 画面下のヒントが 同じ文字を二重に出す

- スクショ 05 / 06: 画面中央下の帯「ツムギと はなす」と、右下の丸ボタン「ツムギと はなす」。
- 帯(`.hud-hint`)は タッチのとき `bottom: sa-b+104px`(`style.css:936`)に上げてあるので
  重なりはしないが、同じ文が2か所に出る。

### F-13 【確信度: 低】釣りの「つりあげてる…」の間、丸ボタンが「しらべる(うすい)」に戻る

- 実測(スクショ 50): `.touch-action.dim`「しらべる」。
  「まってる…」→「!! つりあげる」→ 急に「しらべる(うすい)」になるので、
  いま何が起きているのか 丸ボタンからは読めない。

### F-14 【確信度: 低〜中・未検証】仮想スティックの帯だけ safe-area を見ていない

- `src/ui/touch.css:25-32` の `.touch-stick-zone` は `left: 0; bottom: 0` で
  `env(safe-area-inset-*)` を足していない。
  ほかのタッチUIは全部足している(行動ボタン `touch.css:75-76`、エモート `125-126`、
  右上メニュー `171-172`、配置バー `219-220`)。
- iPadOS のホームインジケータのスワイプ帯(画面下 約20px)に指を置くと、
  システムのジェスチャが優先される可能性がある。
- ヘッドレス Edge では `env(safe-area-inset-*)` が すべて 0 なので **実測できていない**。CSS の読みだけ。

### F-15 【確信度: 低】配置モード中でも 右上のパネルボタンが押せる

- スクショ 69: 「まわす」「やめる」が出ているのに、もちもの・クラフト・おねがい・ずかん・メニューも
  出たまま。パネルを開くと 配置バーは隠れる(`TouchControls.ts:376`)が、配置自体は続いている。

### F-16 【確信度: 高・ゲームの問題ではない】検証ボットが2回止まったが、どちらも操舵の問題

- 1回目(第1走): ツムギ工房の建物に押しつけられ、目標まで 15.2m のまま 15分 動けなかった(スクショ 08)。
  まっすぐ目標へ倒すだけの操舵だったため。かべづたい(90度ずらして回りこむ)を足した第2走では
  同じ地点を通過できた。
- 2回目(第3走): 桟橋の手前 9.9m。16方向スイープの実測 →
  `0°:4.37m / 23°〜180°:0〜1.09m / 202°〜337°:5.37〜5.61m`。
  海の方向へは進めず、陸側へは自由に動ける = **海に阻まれているだけ**。詰みではない(スクショ 46)。
  そのあと 経路を変えて 桟橋に着き、釣りまで進めた。

## 5. 実タッチ特有の確認

### ダブルタップ拡大・ピンチ拡大 → **起きない**(実測)

- 実測: キャンバス中央を 70ms 間隔で2回タップ → `{scrollX:0, scrollY:0, visualViewport.scale:1,
  innerWidth:1180, innerHeight:820}` が 前後で完全一致(スクショ 208)。
- 実測: 2本指を (540,300)/(660,420) から ±112px ひろげる → 同じく変化なし(スクショ 212)。
- 根拠:
  - `index.html:6-9` `content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover"`
  - `src/ui/style.css:22-31` `html, body { position: fixed; inset: 0; overflow: hidden; overscroll-behavior: none; touch-action: manipulation; ... }`
  - `src/ui/style.css:33-36` `#game-canvas { ... touch-action: none; }`
  - `src/ui/touch.css:5-16` `#ui-root > .touch-root { ... touch-action: none; }` /
    `src/ui/touch.css:20-22` `.touch-root * { touch-action: none; }`
  - `src/main.ts:118-135` `preventBrowserZoom()`:
    `gesturestart` / `gesturechange` / `gestureend` / `dblclick` を preventDefault、
    `touchmove` は `e.touches.length > 1` のときだけ preventDefault(パネル内の1本指スクロールは残す)、
    `window.addEventListener('scroll', () => window.scrollTo(0,0))` でずれを戻す。
- iOS Safari は `user-scalable=no` を無視するが、`touch-action: manipulation` が ダブルタップ拡大を、
  `gesturestart` の preventDefault が ピンチ拡大を止める。両方そろっているので 実機でも拡大しない見込み。

### 長押しの選択メニュー → **出ない**(実測)

- 実測: キャンバス中央を 1.4秒 長押し → `window.getSelection()` の文字数 **0**(スクショ 209)。
  ポーズメニューの見出しの上でも **0**(スクショ 210)。
- 根拠: `src/ui/style.css:27-29`
  `-webkit-user-select: none; user-select: none; -webkit-touch-callout: none; -webkit-tap-highlight-color: transparent;`
  タッチUIの根にも同じ4つ(`src/ui/touch.css:11-14`)。

### 安全域(`env(safe-area-inset-*)`)

- `index.html:8` `viewport-fit=cover`(ノッチ・ホームインジケータの下まで描く)。
- `src/ui/style.css:13-16` で `--sa-t/-r/-b/-l` を作り、HUD・パネル・会話・トースト・
  フォトモードが すべて足している
  (`style.css:96,127,157,175,352,567,707,874,894,931,932,936,939,945,1009,1019,1038-1049`)。
- `src/ui/touch.css` も `env()` を直接足している(行動ボタン 75-76 / エモート 125-126 /
  右上メニュー 171-172 / 配置バー 219-220)。
- `src/main.ts:78-99` が `visualViewport` の実寸を `--app-w/--app-h` に入れ、
  `#game-canvas` と `#ui-root` の大きさを決めている = Safari のアドレスバーが出入りしても
  UI が画面の外へ出ない作り。
- **足りていないのは `.touch-stick-zone` だけ**(F-14)。
- ヘッドレス Edge では `env()` が 0 なので、安全域そのものは 実測できていない。

### カメラ操作
