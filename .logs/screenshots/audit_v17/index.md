## 注記

1. **誘導マーカーの写り込み** — 07/08/09/09b/10 に画面下の方向矢印(`.dir-arrow`)が写っている。
   帰り道の案内(「ふねで しまへ もどろう」「でんしゃで しまへ かえろう」)で、入り江・いちば島では
   依頼を全部終わらせても消せない。**10 だけは 3Dの光の柱(beacon)も出ている**
   (不透明度0.1〜0.2・目標まで7m超のときだけ表示。景色にはほぼ溶けているが、写っていることは事実)。
   それ以外の22枚には光の柱も矢印も写っていない。

2. **ルミの木とじゅえきの木は、追従カメラでは てっぺんが入らない** — ルミの木の実測の高さは 6.89m。
   追従カメラは見下ろし角が固定(`CAM_HEIGHT 4.9 / CAM_LOOK_UP 0.95`、pitch は 0.6〜1.7 でしか動かない)で、
   いちばん引いて・いちばん低くしても(zoom 1.6 / pitch 0.6)画面の上ふちは水平より約3度上までしか届かない。
   01〜03・15・16 は「実プレイで見える範囲」であり、木の全体は **01b(自由カメラ)でしか撮れない**。

3. **カメラは1枚も地表より下へ行っていない** — 全27枚で `カメラの高さ − 地面の高さ` を実測し、最小 +0.41m(B2)。
   追従カメラ側は `CameraController.update` が `terrainHeight+0.6` で持ち上げるので構造的に潜らない。

4. **走行中に描画解像度の段が2回下がった(重要)** — 27枚は同じ解像度で撮れていない:
   - 1769x1229(CSS の 1.5倍・ねらいどおり): 01, 01b, 02, 03, 04, 05, 06, 07, 15, 16, 17
   - 1539x1069(1.3倍): 08, 09, 09b
   - 1361x946(1.15倍): 09c, 10〜14, 13b, B1〜B6
   原因は `src/perf/DynamicResolution.ts`(`main.ts` の DRS)。ログ実測:
   `[dynres] step 1/3 scale 0.6667 -> 0.7667 p95=32.75ms t=35s` / `step 2/3 -> 0.8667 p95=31.50ms t=53s`。
   **この計測中は別の検証が同じ機械で同時に走っていた**ので、この段下がりは環境起因の可能性が高い(確信度 中)。
   別ライン(`main.ts:164 setupAdaptiveResolution`)も 40秒の単独計測で1回発火した
   (`renderscale_probe.json`: fps中央値 64.9 なのに 10〜12秒めに 10/10/3.5fps の谷 → 1.5 から 1.25 へ。
   **fps が 65 に戻っても解像度は元に戻らない**)。
   なお **ねらいどおりでも 3D は CSS の1.5倍までしか描かない**(`main.ts` `MAX_RENDER_SCALE = 1.5`)。
   iPad(dpr=2)では 1769x1229 を 2360x1640 へ引きのばして表示している。

5. **測り方** — 天気は `?weather=rain` / `?weather=snow` で強制(`GameScene.ts:128` の FORCE_WEATHER)。
   室内・入り江・いちば島は `game.applyIndoor/applyNpcHome/applyCove/applyMarket` を直接呼んで移動。
   まつりは 28日め(7の倍数)18:30 に人が輪へ集まりきるまで待ってから撮影(5人集合を確認)。
   B5 は「話しかけられた NPC はこちらを向く」性質を使って正面を作った
   (キャラは `rotationQuaternion` で回るので `mesh.rotation.y` からは正面が出せない)。

6. console エラーは **27枚すべてで 0件**。
