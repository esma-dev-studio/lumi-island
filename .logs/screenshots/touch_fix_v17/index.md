# touch_fix_v17 — iPadタッチ監査(touch_audit_v17)の手当ての 再撮影・再計測

検証日: 2026-09-08 / dev サーバー: `http://localhost:5227/?scene=game&debug=1`
ハーネス: `tools/shots_touch_fix_v17.mjs`(ヘッドレス Edge・iPad 1180x820 / たて 820x1180・dsf2・hasTouch)

- 画面の操作は **page.touchscreen の tap / touchstart→touchmove→touchend だけ**。キーボードは1度も押していない。
- `debug=1` は「同じ場面をそろえる」ためだけ(レシピ・依頼・持ちもの・立ち位置)。押す・スクロールはすべて指。
- `*_after.png` = 直したあと。`*_before.png` = **直す前の CSS を 同じセッションで 上書き再現**したもの
  (実コードを 巻きもどしたものではない。JS側の手当て——目標レシピへのスクロール・丸ボタンの判定・
   配置中のボタン整理——は before では 打ち消せないので、その3つは before の判定を 自動で合格にしてある)。
- 生の計測値: `_measure_after.json` / `_measure_before.json`(全要素の 大きさ・font-size・スクロール率)。

## 判定

`after`: **25/26 OK**(console エラー 0件 / 44px未満のタップ対象 0件 / 14px未満の文字 0件)
`before`: 19/24 OK

のこる 1件は **今回の16件の外**の、もとからある はみ出し:
もちものの 1マスで「おく」ボタンが マスの右わくを **before +14px / after +17px** 越える
(パネルの外へは 出ない・44px以上で 押せる)。
`.inv-name` の「4文字ぶん(4em)を かならず のこす」決まりと、1マスの幅(169px)が
もともと 合っていない。文字を 13.32→14.04px にしたぶん 3px ふえた。
直すなら `html.touch-ui .inv-slot:has(> .craft-btn) .inv-name { min-width: 0 }` の1行だが、
v14の「名前が1文字ずつ 縦に割れる」手当てに かかわるので **今回は 手を入れず 報告だけ**。

## 手当てで 出た かねあい(トレードオフ)

- **クラフトを開くと タブ(レシピ / くみあわせ)が 画面の外に出る。**
  目標のレシピまで 459px スクロールするので、一覧の いちばん上にある タブは 上へ流れる。
  見出し(`.panel-title`)は くっついたままなので「クラフト」と「とじる」は いつでも 見えるが、
  タブへは いちど 上へ はらう必要がある。タブも くっつける手はあるが、
  節見出し(`.craft-sec`)の くっつく位置と 3段になるので **今回は 見出しだけ**にした。
- **ポーズ画面だけ 帯を付けていない。** ここは `display:flex` の たて1列で
  「パネルは 流れず 中の そうさほうほうだけが 流れる」作り(v16.1)。
  帯を たすと パネルまで 流れてしまう(e2e `ui_wave_v161` が 機械検査している)。

## この検証で 分からないこと

- ヘッドレス Edge(Chromium)なので、**実機 Safari 固有の挙動は 未検証**:
  `env(safe-area-inset-*)` の実値(すべて 0px で計測)、慣性スクロール、ホームインジケータのジェスチャ、
  `:has()`(Safari 15.4+ で対応。使えない環境では 目標カード・トーストが 直す前の置き場所に もどるだけ)。
- F-09(そうさほうほうが よこむきで 42%しか読めない)は **今回スコープ外**(TitleScreen.ts は別担当)。
