# 鉱石依頼 399秒問題の原因分析(v4 P0-2)

- 事象: v3回帰走行(全体11分34秒)で `q_ore_gather` が **175秒→574秒 = 399秒** を占めた。
- 分析日: 2026-07-30

## 計測1: 鉱石への到達性(高台入口22,-26からボットと同じ操舵で直進)

| 鉱石 | 到達 | 所要 | スタック回数 | 最小接近距離 |
|---|---|---|---|---|
| ore1 (32,-24) | 到達 | 3.0秒 | 0 | 1.30m |
| ore2 (27,-34) | 到達 | 7.7秒 | 0 | 1.44m |
| ore3 (35,-30) | 到達 | 6.3秒 | 0 | 1.22m |
| ore4 (30,-21) | 到達 | 2.6秒 | 0 | 1.33m |

→ **地形・坂・埋まり・当たり判定は問題なし**。全鉱石に2.6〜7.7秒で到達でき、
衝突による停止は0回。「登れない」「埋まっている」「壁が塞ぐ」仮説はすべて棄却。

## 計測2: 消去法とコード検証で確定した真因

**ノクト本人が採取のEを横取りしていた。**

1. q_ore受注中、ノクトは questCritical のため高台の定位置 **(30,-26)** に常駐し、
   watch活動で半径約2.2mをうろつく。
2. 定位置(30,-26)は ore1(32,-24) から **2.7m**、ore4(30,-21) から5m。
   うろつきでプレイヤー(鉱石前)から1.8m以内に入ることが頻繁にある。
3. Eキーの候補解決(InteractionResolver)は「依頼があるNPC=優先度10」>「採取=優先度30」。
   進行中(progress)の依頼でも優先度10のままだったため、鉱石の前でEを押すと
   **採取ではなくノクトとの会話(進捗セリフ)が開く**。
4. ボット(=プレイヤー)は「鉱石へ移動→E→会話が開く→閉じる→また移動→E→会話…」を
   ノクトが偶然離れるまで繰り返す。これが399秒の正体。
   (同じ構成でも彼のうろつき位置次第で14秒で終わる走行もあり、再現が確率的である点とも一致)

## 修正

1. **候補優先度の是正**(`src/scenes/InteractionRouting.ts`):
   会話が意味を持つのは mode が offer(受注できる)/done(報告できる)のときだけ。
   進行中(progress)のNPCは優先度を「採取より下(gather+5)」へ変更。
   → 鉱石の前のEは必ず採取になる。受注・報告はこれまで通り最優先。
2. **ノクトの高台定位置を鉱石帯の外へ移動**(`src/data/island.ts` NPC_SPOTS.nokto.hill):
   (30,-26)→鉱石から4m以上離れた観測スペース側へ。P1-4の高台再設計と合わせて調整。
3. **採取系Objectiveの誘導先を「最寄りの未採取ノード」へ動的化**
   (`InteractionSystem.nearestActiveNode` + `GameScene.targetPosOf`):
   マーカー・矢印・距離が採取済みノードやエリア中心ではなく、次に採るべき実ノードを指す。
   林の木材でも同様に効くため、UXボット(P0-3)の視覚探索問題も同時に解消する。

## 修正後の受入計測(2026-07-31 回帰ボット実走)

| 受入条件 | 目標 | 実測 | 判定 |
|---|---|---|---|
| 高台入口→最初の鉱石 | 20秒以内 | 到達性プローブで2.6〜7.7秒 | 合格 |
| 鉱石3個の採取 | 90秒以内 | **13秒**(02:37→02:50) | 合格 |
| 受注→報告 | 3分以内 | **30秒**(02:24受注→02:54次依頼へ) | 合格 |
| 15秒以上の停滞 | なし | ハートビート上の停滞なし | 合格 |
| 採取済み鉱石を指し続けない | — | nearestActiveNodeForItemで次の未採取へ切替(ユニット4件) | 合格 |

**399秒 → 30秒(93%短縮)**。同走行の全体時間も 11分34秒 → **5分29秒**(エラー0・平均50FPS)。
副次効果として、2個目のいしのランプ用の再採取(リスポーン待ち込み)も
q_lumi_mats_stone→ore→craft が 04:48→05:10 の22秒で完了しており、動的マーカーが機能している。
